# 项目介绍：接口自动化测试平台

> 读者：第一次接触本项目的研发 / 测试 / 管理者。
> 想直接上手操作请读 [USER_GUIDE.md](USER_GUIDE.md)；想查具体语法请读 [FRAMEWORK.md](FRAMEWORK.md)。

## 一、这个项目是什么

一套**数据驱动的接口自动化测试平台**，当前用于 mall4j 电商管理后台的接口测试。

核心主张只有一句话：

> **用例是数据，不是代码。** 测试同学在 Excel 里填「调哪个接口、传什么参数、断言什么」，
> 框架负责登录、发请求、验断言、造数据、清数据、出报告。

在这之上，项目还多做了两件事：

1. **质量闸门** —— 不允许"只断言 `status_code == 200`"的薄用例进库，不允许把环境故障当用例 Bug 改断言；
2. **AI 与智能体接入** —— 用例生成、失败归因、知识图谱、自愈闭环，以及 27 个 MCP 工具，让 Claude Code 这类智能体能直接驱动整套框架。

---

## 二、解决什么问题

接口自动化测试常见的几类失败，这个项目分别有对策：

| 常见问题 | 本项目怎么做 |
|---|---|
| 每条用例都要写 Python，测试同学改不动 | Excel / YAML 数据驱动，新增用例零代码 |
| 登录态每套脚本各写一遍，token 过期就全挂 | 统一登录适配 + token 缓存 + 按项目触发的登录链路 |
| 用例跑完留一堆垃圾数据，或误删真实数据 | 正例自带「造数 → 查 id → 按 id 删除」链路；写操作过安全闸 |
| 接口返回 200 就算过，bug 全漏 | 强制业务断言 + 查库断言（HTTP 200 ≠ 真落库） |
| 挂了以后分不清是谁的锅，乱改用例 | 失败归因四分类：环境 / 用例数据 / 服务缺陷 / 框架脚本 |
| 报告只有一堆红点，看不出业务影响 | allure 三层业务树（项目 → 模块 → 场景）+ 中文标题 + 归因附件 |
| AI 生成一堆用例，没人敢用也没人清理 | 沙箱模块隔离（`ai_*`）、默认 `draft` 不进 CI、生命周期提示 |

旁路（只调用能力层，不被调用）：
  ai/     用例生成 / 缺陷诊断 / 知识图谱 / 智能体工具 / MCP 服务 / 评测集 / 规则包

## 四、核心设计

### 4.1 一次运行的链路

```
python scripts/run.py --module admin_area
  → 读 config.yaml（环境 / 用例来源 / 限流 / 安全闸）
  → 按 case_source 扫用例目录（Excel 或 YAML）
  → 拼 pytest 参数，子进程启动 pytest
      → 收集用例 + 参数化展开
      → 按模块 order 排序，最长优先
      → 登录（按项目档案，mall4j 走滑块）并缓存 token
      → 逐条执行：setups → 主步骤（steps）→ 断言 → teardowns
      → 失败归因（环境抖动会自动重试，断言失败不重试）
  → 出报告（allure / HTML / result.json）+ 终端汇总
```

### 4.2 用例模型

一条用例由四段构成，全部是数据：

```
setups     前置：造数据、查 id            （失败则主步骤不执行，但 teardown 仍会跑）
steps      主步骤：发请求 + 断言           （这是用例的"验证主体"）
teardowns  后置：按 id 精确清理            （只做清理，不承担验证职责）
status     状态机：debugged / draft / disabled / broken
```

两种落盘格式：

| 格式 | 目录 | 结构 | 适用 |
|---|---|---|---|
| **Excel（默认）** | `testcases/cases_excel/` | 四张表（模块信息 / 接口定义 / 测试用例 / 说明） | 人工维护，产品/测试都能改 |
| **Excel 大表** | 同上 | 一张「接口测试用例」表，一行一条，断言写 JSON | 脚本生成（Swagger/Postman 导入） |
| **YAML** | `testcases/cases/` | 一条用例一个文件 + `data/` 参数化 | 复杂场景、代码风格维护 |

### 4.3 登录态

- 登录方式按「项目档案」配置（`login.type`：`slider / custom / password`）；
- mall4j 使用 `adapters/mall4j.py` 的自定义链路：取拼图验证码 → 识别缺口 → POST 校验 → AES 加密密码登录；
- token 缓存到 `.cache/`，过期或 401 自动重新登录；
- 用例里只写 `{{mall4j.token}}`，不需要关心登录细节。

### 4.4 数据安全（三道闸）

1. **生成阶段**：清理步骤里的固定 id 会被剥落，必须引用「查数步骤」查出来的 id；
2. **运行阶段**：`safety_guard` 拦截对保护路径（地区/菜单/角色/商品…）的危险写操作，
   目标 id 必须落在安全区间（默认 `900000000000-999999999999`）；
3. **存量检查**：维护脚本扫描存量用例里的硬编码删除 id。

### 4.5 失败归因

失败不是一律算「用例挂」：

| 归因 | 判据 | 处置 |
|---|---|---|
| 环境问题 | 网络超时、连接拒绝、5xx、限流 | 自动重试；仍失败则标记环境阻塞，**不改用例** |
| 用例数据问题 | 前置数据不存在、id 失效 | 允许修改用例（造数链路 / 断言） |
| 服务缺陷 | 业务码异常、落库不一致 | 提缺陷，**禁止**放宽断言 |
| 框架问题 | 抛栈、内部异常 | 修框架 |

自愈流程按归因决定可用动作：环境问题只重跑、服务问题只提缺陷、只有用例数据问题才能改，
并且改完必须重跑验证（不过自动回滚）。

## 五、AI 能力层

```
ai/capabilities/   用例生成（规则优先，LLM 可选）、LLM 客户端、缺陷诊断
ai/pipeline/       生成流水线：维度覆盖、意图识别、造数编排、环境探针
ai/knowledge/      知识图谱：接口 ↔ 参数 ↔ 表列 ↔ 用例，混合召回
ai/rules/          用例规则包 + 校验器（质量闸门）
ai/agent/          27 个智能体工具 + 自愈状态机 + 审计日志
ai/mcp_server/     MCP 服务端（stdio），接 Claude Code / Cursor
ai/evals/          评测集与机械判分（防"改了提示词变差没人知道"）
.claude/skills/    /apitest-run  /apitest-author  /apitest-heal  /apitest-coverage  /apitest-design
.claude/agents/    执行员、分析员两个专职 subagent
```

**几个关键约束**（都有回归测试盯着）：

- 工具必须诚实声明副作用（`read / execute / write_case / write_real`），权限策略按这个字段配；
- 写类工具只认 `case_id`（如 `API-168`），不认文件路径和用例名 —— 路径可以编，编号抄错会明确报错；
- 改断言只能变强：删断言、放宽比较符会被拒绝；
- `run_cases` 三道边界闸：必须带筛选条件、单次 ≤ 50 条、单会话累计 ≤ 50 条；
- AI 生成的用例落沙箱模块（`ai_*`），默认 `draft`，不进 CI；
- **没有 LLM key 也能用**：生成退回本地模板，诊断退回规则分类。

## 六、质量体系

用例质量不是靠自觉，是靠闸门：

| 闸门 | 检查什么 | 位置 |
|---|---|---|
| 用例 Schema | 结构合法性 | `utils/cases/case_validator.py` + `schemas/` |
| 规则校验 | 断言强度、命名、正例造数、清理安全性 | `ai/rules/validator.py` |
| 断言盘点 | 哪些用例只有弱断言 | `tools/maint/survey_assertions.py` |
| 落库断言盘点 | 哪些写操作没验落库 | `tools/maint/audit_db_assertions.py` |
| 质量盘点 | 存量用例按闸门体检 | `tools/maint/audit_quality.py` |
| 评测集 | 智能体行为是否退步 | `ai/evals/` + `scripts/run_eval.py` |

框架自身有 **1260 条单元测试**（不联网，约 20 秒跑完），覆盖解析、断言、参数化、依赖、
安全闸、归因、自愈、MCP 协议等。

## 七、可观测性

- **日志**：`logs/YYYY-MM-DD.log` + `.error.log`，按天分文件，自动保留 7 天，敏感字段脱敏；
- **报告**：allure（三层业务树 + 请求/响应分附件 + 失败归因）、HTML 报告、`reports/result.json`；
- **报告保留**：只保留最近 10 份 allure 目录（`APITEST_REPORT_KEEP` 可调），防止 reports/ 无限增长；
- **审计**：智能体每次工具调用落 `.cache/agent_audit.jsonl`（参数/结果/耗时/token，已脱敏），
  可用 `get_agent_audit` / `get_agent_cost` 回看。

## 八、适用边界

**适合**：HTTP 接口为主的业务系统、需要人工可维护的用例集、需要查库验证落库、
需要接 CI 和智能体的团队。

**不适合 / 需额外开发**：纯 UI 自动化（当前只做登录页的滑块识别）、
强状态机的长链路压测、需要真并发压测的场景（限流器是保护被测环境的，不是压测工具）。

## 十、下一步可以做什么

- 补齐 `disabled / broken` 状态用例的修复或退役；
- 覆盖 OpenAPI 快照里尚未被用例覆盖的接口（`get_coverage` 可列清单）；
- 给关键写接口补落库断言（`tools/maint/add_db_assertions.py`）；
- 把 AI 沙箱里验证成熟的用例提升为正式用例（`set_case_status` → debugged）；
- 接更多被测系统：只需要在 `configs/config.yaml` 的 `projects` 下加一份项目档案和登录适配。
