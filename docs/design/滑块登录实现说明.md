# 滑块登录实现说明（mall4j）

> 本文记录 mall4j 管理后台登录链路的**实现细节和踩过的坑**。
> 普通使用者不需要读它 —— 用例里只写 `{{mall4j.token}}`，框架会自动完成这里描述的一切。
> 要改登录适配、排查滑块识别问题、或接入新的滑块系统时再看。

---

## 一、登录链路

```
① 取验证码      GET  /captcha/get?verificationEnums=LOGIN
                    → 返回 backImage / slidingImage / uuid
② 识别缺口      本地图像算法算出 xPos（不开浏览器也能算，浏览器只用来取图）
③ 校验           POST /captcha/get?verificationEnums=LOGIN&xPos=<x>&key=<key>
                    → success=true 且 result 是 dict（下一题数据）
④ 登录           POST /passport/login
                    请求头 Authorization: Bearer <uuid>
                    请求体账号 + AES 加密密码
                    → 返回 accessToken / refreshToken
⑤ 调业务接口     请求头 Authorization: <accessToken>（头名按项目档案 token_header）
```

代码位置：

| 环节 | 文件 |
|---|---|
| 登录适配入口 | `adapters/mall4j.py`（`login()`） |
| 拼图缺口识别 | `utils/slider/gap_shape_v2.py`（主）、`gap_shape.py` / `gap_detect.py`（备） |
| 浏览器取图 | `utils/slider/browser_slider.py` |
| uuid / 会话 | `utils/slider/uuid_util.py`、`utils/http/request_util.py` |
| 业务客户端 | `utils/http/api_client.py` |
| 按项目触发登录 | `testcases/project_login_handler.py` |

## 二、三个关键坑

### ① `slidingImage` 不能直接当模板做 matchTemplate

服务端下发的拼图块是**从背景图上挖下来的那一块**，本身已经不含背景内容。
拿它去匹配背景图，匹配的是"被挖走后的空洞纹理"，实测匹配分只有 0.2~0.5，位置基本随机。

正确做法：拼图块图片**带 alpha 通道**，不透明区域就是拼图块的精确形状（jigsaw 轮廓）。
把这个形状贴到背景图上，找"形状内部最暗 + 轮廓最吻合"的位置。实测一次命中率 8/8。

### ② 校验接口必须是 POST，用 GET 会假通过

```
GET  /captcha/get?verificationEnums=LOGIN&xPos=123
  → {code:200, success:true, result:{...下一题数据...}}   # 传任何 x 都放行！

POST /captcha/get?verificationEnums=LOGIN&xPos=123
  → {code:200, success:true, result:{...}}                 # x 正确
  → {code:80202, message:"验证失败", result:null, success:false}   # x 错误
```

服务端把 GET 当成"取下一题"，**不校验 xPos**。用 GET 写测试会出现"传错 x 也通过"的假象。

### ③ 校验通过时 `result` 不是 `true`，而是下一题的初始化数据

对照前端 JS：

```js
e.success ? (e.result ? "解锁成功" : "解锁失败") : "重试"
```

- 通过：`success=true`，`result` 是 dict（含 backImage / randomY / key…）
- 失败：`success=false`，`result=null`，`code=80202`
- 限流：`code=1003`「访问过于频繁」

**判据是 `success is True and bool(result)`。**

## 三、uuid 是一次性凭证

后端按 `uuid` 维护会话，并在滑块通过之后**消费**掉。同一个 uuid 第二次用会返回：

```json
{ "code": 80204, "message": "验证码已失效，请重新校验" }
```

更麻烦的是：**uuid 被消费之后，服务端对同一 uuid 的后续请求会直接放行**，
连 xPos 都不校验。所以"错误输入应该失败"这类反向用例必须用**全新的 uuid**，
否则会假通过。

- 框架自动处理：登录前取新 uuid，失败自动换新重试（默认 3 次）
- 用例里手写：`{{tools.fresh_uuid()}}`
- 手动抓一个（排查用）：

```powershell
.venv\Scripts\python.exe -c "from utils.tools import fresh_uuid; print(fresh_uuid())"
```

解析优先级：环境变量 `MALL4J_UUID` > `config.yaml` 里的 `uuid` > 现场抓取。

## 四、鉴权头

| 阶段 | 头 | 值 |
|---|---|---|
| 登录接口 | `Authorization` | `Bearer <uuid>`（会话标识，走滑块） |
| 业务接口 | `Authorization`（`projects.mall4j.*.auth.token_header` 配置的头名） | `<accessToken>`（**不带 `Bearer`**，按原样填） |

用错头会拿到：

```json
{"code":403,"success":false,"message":"未登录或token失效"}
```

这个坑很隐蔽 —— 前面所有步骤都成功，只有最后调业务接口时才炸。
`utils/http/api_client.py` 已封装好；用例里统一写 `Authorization: {{mall4j.token}}`
（具体头名由 `configs/config.yaml` 的 `projects.mall4j.*.auth.token_header` 决定）。

## 五、密码与凭证

- 密码**只放 `.env` 或环境变量**（`MALL4J_USERNAME` / `MALL4J_PASSWORD`），
  `configs/config.yaml` 里是 `${MALL4J_PASSWORD:}` 占位符；
- 写进 config 的密码是明文，运行时由适配器做 AES 加密，**不要自己预先加密**；
- 日志和报告附件会自动脱敏（token / 密码 / 手机号 / 身份证）。

---

## 六、缓存与重试

- 登录成功的 token 缓存在 `.cache/`，下次运行直接复用；
- 业务接口返回鉴权失败（A00004）时会自动重新登录并重发一次；
- **做未登录 / 反向用例时要显式跳过鉴权**（`skip_auth`），否则会被自动重登录"救回来"，
  导致反向用例假失败；
- 滑块识别失败自动换 uuid 重试 3 次；登录整体有超时上限（默认 5 分钟），超时放弃该条用例继续跑。

管理登录缓存：

```powershell
python scripts\run.py --show-cache
python scripts\run.py --clear-cache
python scripts\run.py --no-cache
```

## 七、调试图

`configs/config.yaml` 里 `slider.save_debug: true`（默认开）时，每次识别会在 `data/debug/` 落三张图：

| 文件 | 内容 |
|---|---|
| `{ts}_slider.png` | 背景图 |
| `{ts}_slider_piece.png` | 拼图块（能看到 alpha 形状） |
| `{ts}_slider_marked.png` | 背景图 + 绿框标出预测位置 |

框偏了就是算法问题，不用怀疑报文。日志里会打印三路算法（形状 v2 / 形状 v1 / 暗度）的结果，
三者不一致时说明这题纹理复杂，可调 `gap_shape_v2.py` 的权重。

## 八、登录用例怎么写

用例层不要手写这套链路，用特殊步骤：

```yaml
steps:
  - id: login
    operation_type: login          # 完整滑块链路
    username: '{{tools.login_credential("mall4j", "username")}}'
    password: '{{tools.login_credential("mall4j", "password")}}'
    assert:
      - type: equal
        field: code
        expected: 200
```

三种特殊步骤：

| operation_type | 作用 |
|---|---|
| `login` | 完整链路：抓 uuid → 识别 → 校验 → 登录 |
| `login_no_slider` | 抓新 uuid 后直接调登录接口（验证服务端会拒绝） |
| `noop` | 不发请求，只跑断言（跨接口比对用） |

完整写法见 [FRAMEWORK.md](../FRAMEWORK.md) 的「七之三、登录用例怎么写」。
